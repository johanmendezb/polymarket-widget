## Scope: T4.1 only — the widget shell and layout system

Do **not** build search, market detail, the order preview or confirmation. Those are T4.2 through
T4.5 and they depend on this. You are building the shell they mount into.

Read `docs/01-product/USER_FLOWS.md` for the states this shell has to host, and
`docs/02-research/UX_RESEARCH.md` §1.3 only if the layout decisions need justifying.

## The constraints that are unusual, and why

This renders inside a **sandboxed iframe on someone else's page**. That invalidates three habits:

- **Container queries only.** A media query keys off the host page's viewport, not the widget's
  box, so it produces confidently wrong layouts. The widget must be correct at **380px and at
  1200px** driven purely by its own container width. ADR-0014.
- **No `localStorage`, `sessionStorage` or cookies.** A sandboxed iframe has none of them. Not
  "avoid" — they are unavailable, and code that assumes otherwise fails only in the real embed.
- **Theme is an explicit parameter**, passed by URL param or `postMessage`. CSS does not cross an
  iframe boundary, so the widget cannot inherit the host's theme. Support light and dark via
  `color-scheme` and `light-dark()`.

## Build against a fixture, not against real data

The UI consumes a typed `Recommendation`. Build against a fixture one so this task does not block
on E3 or E5 — that independence is exactly why the roadmap runs the UI shell and the AI route in
parallel.

## Also

- No `dangerouslySetInnerHTML` anywhere. Model output is text. Lint enforces this.
- `src/ui` may import `domain`, `simulation` and `lib` — never `polymarket` or `app/api`.
- Loading skeletons must match the final layout's dimensions, or every load shifts the page.
- Keyboard completability is an acceptance criterion for the epic, so build focus management in
  now rather than retrofitting it in T7.1.
- Do not write tests that assert only that a component rendered. Test the states that matter.

## Acceptance criteria

1. The shell renders correctly at 380px and 1200px, driven by container queries. Prove it with a
   test or a Playwright screenshot at both widths, not by eye.
2. Light and dark both render correctly from the explicit theme parameter.
3. No `localStorage`, `sessionStorage` or cookie usage anywhere — grep and show the result.
4. `pnpm lint` passes, including the import-boundary rule for `src/ui`.
5. A fixture `Recommendation` renders through the shell without any network call.
