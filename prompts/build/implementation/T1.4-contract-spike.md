## Objective

Prove the documented Polymarket read behaviour against production, and freeze real responses as
dated test fixtures that every later epic tests against.

## What is already verified — assert these, do not re-derive them

The orchestrator probed the live API on 2026-08-16 across eight markets. Your job is to turn these
into standing assertions and fixtures, not to rediscover them. If any assertion **fails**, that is
a real finding: stop and report it rather than adjusting the assertion to match.

1. **Both book sides arrive worst-price-first.** `asks` descending, `bids` ascending. The best
   level is the **last** element of each. This corrects an earlier doc revision that claimed both
   arrived descending. Assert both orderings separately.
2. **Token ids are 77-digit strings** exceeding `Number.MAX_SAFE_INTEGER`.
3. **`clobTokenIds` is a JSON-encoded string, not an array** — `"[\"7214...\",\"2714...\"]"`.
   So are `outcomes` and `outcomePrices`. Assert all three parse to equal-length arrays.
4. **`clob /book` is snake_case**: `asset_id`, `last_trade_price`, `min_order_size`, `neg_risk`,
   `tick_size`, `hash`, `market`, `timestamp`.
5. **A request with no `User-Agent` gets 403** from the CLOB host; an ordinary UA gets 200. The
   recorder and the client must send an explicit UA. Assert this explicitly — it is OQ-10 and it
   would otherwise surface in production as a mystery 403.
6. **Fee fields are frequently absent.** A live liquid market returned `feesEnabled: false`,
   `feeType: null`, `takerBaseFee: null`. Assert the *keys* are reachable; do **not** assert they
   are populated, and never let an absent field imply a zero rate.

## Requirements

Write `scripts/record-fixtures.ts`, wired to `pnpm record-fixtures` (T1.1 left it a stub). It calls,
unauthenticated but with an explicit User-Agent:

- `GET gamma /public-search?q=election`
- `GET gamma /markets/{id}` for the first market found
- `GET clob /book?token_id={...}` for a **liquid** token and for an **illiquid** one
- `GET clob /prices-history?market={...}&interval=1w&fidelity=60`

and writes raw, unmodified JSON to `test/fixtures/`. Tag every fixture with the date recorded —
put it in the filename or a sidecar, your call, but a reader must be able to tell a fixture's age
without running anything.

Record a genuinely **thin** book as well as a liquid one. E2 needs a thin-book fixture to test
partial fills and the "insufficient depth" path, and picking one now is free.

Then write the live contract suite, wired to `pnpm test:live`, asserting points 1–6 above plus the
market object exposing `feesEnabled`, `takerBaseFee`, `orderPriceMinTickSize`, `orderMinSize`,
`negRisk` and `acceptingOrders`.

**`pnpm test:live` must be excluded from CI and from `pnpm test`.** No live network in CI, ever —
a flaky demo-day test is worse than no test. Make the exclusion structural (a separate Vitest
project or config), not a naming convention someone can forget.

## Acceptance criteria

1. Fixtures written to `test/fixtures/`, dated, including one liquid and one thin book.
2. `pnpm test:live` passes locally against production.
3. `pnpm test` does **not** hit the network, proven by running it with the network unavailable or
   by showing the config excludes the live project.
4. `pnpm typecheck && pnpm lint && pnpm test` green, zero warnings.
