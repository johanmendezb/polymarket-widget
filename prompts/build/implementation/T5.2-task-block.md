## Scope: T5.2 only — the Anthropic client and k-sampling

T5.1 is done and on your branch: prompts load from `prompts/runtime/` by file, `BlindPromptInput`
has no price field, and `promptVersion` derives from the filename. Build on it; do not redo it.

Do **not** build the forecast route, the blend, or the gate wiring. Those are T5.3.

Read `docs/05-ai/AI_SYSTEM.md` and the T5.2 contract. ADR-0005 fixes the model as
`claude-opus-5`, server-side only.

## This is the highest-risk task in the backlog

It is the only one marked `risk: high`, and the reasons are latency, cost, schema violations and
unbounded time. Every mitigation below is non-optional.

- **A hard timeout.** `AI_TIMEOUT_MS`, default 45000. A hung call must not hang the route.
- **Retry exactly once** on a schema violation, then return `AI_INVALID_OUTPUT`. Never partially
  render, never retry in a loop.
- **k parallel calls**, `AI_SAMPLES`, default 5. They must be genuinely concurrent, and one
  failing sample must not fail the batch — aggregate over what returned, and report how many did.
- **Forced tool use.** `tool_choice` requires `submit_forecast`; a prose response is not an
  acceptable answer and must be treated as a schema violation.

## Aggregation, precisely

- **Median of log-odds**, not median of probabilities. Convert each sample to log-odds, take the
  median, convert back. Clamp inputs away from exactly 0 and 1 first or the conversion is
  infinite — the evaluation doc's worked cases include samples at 0.01 and 0.99, so use them as
  test cases.
- **Dispersion is the IQR across samples**, and it is the *only* uncertainty measure. There is no
  self-reported confidence field and there must never be one: measured dispersion predicts error
  better than a model's own confidence claim. See `docs/05-ai/EVALUATION.md`.
- Test k=1, k=5, and k=5 with one outlier, plus samples at the 0.01/0.99 boundaries.

## Abstention is a success path

`insufficient_evidence: true` is a correct answer, not an error. It flows through as a valid
result with its own shape. Do not coerce it into a probability, and do not let it become an
exception.

## Secrets and logging

- `ANTHROPIC_API_KEY` is read server-side only. **Never** `NEXT_PUBLIC_`. CI greps for it.
- **Never log a full prompt or a full model response** — either may echo configuration. Log the
  model id, prompt version, k, dispersion and latency. Never a key, prefix, length or hash.
- **The key is not set in this environment yet.** Do not ask for it, do not look for it, and do
  not write a test that needs it. Everything here is testable with a mocked SDK client, which is
  what `TEST_STRATEGY.md` requires anyway — no live network in CI, ever. Design the client so the
  transport is injectable, precisely so the tests never need a key.
- Missing key at runtime must produce a clean handled error, not a stack trace.

## The anchored diagnostic

A single call (k=1) using `anchored-v1.md`, which *does* receive the price. It exists only to
measure how far the estimate moves. It is never displayed as the estimate and never enters the
blend. Keep it structurally separate so it cannot be confused with the blind result.

## Acceptance criteria

1. k parallel calls, with one failed sample not failing the batch, and the surviving count
   reported.
2. Median-of-log-odds and IQR dispersion match hand-computed values in tests, including k=1 and
   the 0.01/0.99 boundary samples.
3. A schema violation retries once, then returns `AI_INVALID_OUTPUT`.
4. A timeout returns `AI_TIMEOUT` and never hangs.
5. `insufficient_evidence: true` returns a valid abstention result, not an error.
6. All tests pass with no network and no API key present.
