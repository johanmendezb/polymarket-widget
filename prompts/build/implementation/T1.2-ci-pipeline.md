## Objective

GitHub Actions running the full quality gate on every push and every pull request.

## Requirements

- Node 22 (`.nvmrc` exists — read it rather than hardcoding). pnpm with a warm cache.
- Jobs: `typecheck`, `lint`, `test`, `build`.
- A **`secret-leak`** step that runs after `pnpm build` and greps the built client bundle
  (`.next/static`) for the literal `ANTHROPIC` and for the Anthropic key prefix. A match fails the
  build. This is the check that makes rule 7 in `CLAUDE.md` enforceable rather than aspirational.
- Also run `pnpm audit` per `ARCHITECTURE.md`'s dependency posture.
- The workflow must run on `pull_request` as well as `push`, because branch protection will
  require it as a status check on PRs.

**`pnpm test:live` must never run in CI.** It hits the live Polymarket API. Confirm your workflow
cannot reach it — if `pnpm test` would pull it in, that is a T1.4 bug, so report it rather than
papering over it in the workflow.

Do not add an E2E job yet unless `pnpm test:e2e` already runs green locally; Playwright browsers in
CI are E6's problem, and a red job on main from day one defeats the purpose of this task.

## Acceptance criteria

1. The workflow is green on push.
2. A deliberately introduced type error fails the run. **Prove it and revert it** — push the
   failing commit to your branch, capture the red run, then remove it.
3. A deliberately introduced `NEXT_PUBLIC_ANTHROPIC_API_KEY` fails the `secret-leak` step. Prove it
   the same way, then remove it. Use an obvious dummy value; **never a real key**, and never
   anything shaped like one.

For criteria 2 and 3, paste the run URLs into your handoff. "It would fail" is not evidence.
