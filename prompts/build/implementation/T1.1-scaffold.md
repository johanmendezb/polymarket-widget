## Objective

A Next.js 15 App Router + TypeScript strict project that builds, typechecks, lints and tests.

## Requirements

- **pnpm. Node 22.** Write `.nvmrc` containing `22`. Set `"engines": { "node": ">=22" }` —
  `>=`, not `=`; the owner's machine runs Node 24 and must not be blocked.
- Next.js 15, App Router, `output: 'standalone'` in `next.config.ts`.
- TypeScript `strict: true` **and** `noUncheckedIndexedAccess: true`.
- Vitest configured with a `@/` alias to `src`.
- Directory skeleton exactly as ARCHITECTURE.md §3, each directory containing an `index.ts`
  barrel: `src/domain`, `src/polymarket`, `src/simulation`, `src/ai`, `src/ui`, `src/lib`,
  `src/app/api`.
- ESLint flat config with `import/no-restricted-paths` implementing this boundary table, plus a
  rule banning `dangerouslySetInnerHTML`:

  | Module | May import |
  |---|---|
  | `src/domain` | nothing internal |
  | `src/polymarket` | `domain` |
  | `src/simulation` | `domain` |
  | `src/ai` | `domain`, `simulation` |
  | `src/ui` | `domain`, `simulation`, `lib` |
  | `src/app/api` | everything |

- Scripts: `dev`, `build`, `start`, `typecheck`, `lint`, `test`, `test:e2e`. Also add `warm`,
  `test:live` and `record-fixtures` as stubs that exit 0 with a "not implemented yet (T1.3/T1.4)"
  message, so later tasks fill them in rather than inventing the script contract.
- `GET /api/health` returning `{ status, commit, uptimeSeconds }`, where `commit` reads
  `process.env.RENDER_GIT_COMMIT` and falls back to `"dev"`. `uptimeSeconds` makes a Render cold
  start visible. Do **not** add the `upstream` or `ai` fields — those are T1.3/T7.2.
- The server must honour `process.env.PORT`. Render sets it; a hardcoded 3000 fails the health
  check. This is the single named risk for this epic.

## Install every dependency the project will ever need, now

This is a deliberate deviation from a minimal scaffold and it is load-bearing: four workers will
shortly build `src/simulation`, `src/polymarket`, `src/ui` and `src/ai` **in parallel**, and
`package.json` is the one file they would otherwise all collide on. Install now:

`zod`, `@anthropic-ai/sdk`, `tailwindcss` v4 with `@tailwindcss/postcss`, `msw`,
`@playwright/test`, `vitest`, `@vitest/coverage-v8`, `@testing-library/react`,
`@testing-library/user-event`, `jsdom`, plus the ESLint plugins the boundary rule needs
(`eslint-plugin-import` or `eslint-plugin-import-x`).

**Tailwind v4 is CSS-first and has no `tailwind.config.ts`.** The T1.1 contract's
`files_expected` lists one because it was written before v4. Use v4, and per `CLAUDE.md`
("fix the document in the same commit as the code") correct that line in
`docs/06-execution/BACKLOG.md` in this same commit.

## Acceptance criteria

1. `pnpm install && pnpm build` succeeds from a clean clone.
2. `pnpm typecheck && pnpm lint && pnpm test` pass with **zero warnings**.
3. A file `src/domain/__boundary_probe.ts` importing from `@/polymarket` **fails** `pnpm lint`.
   Prove it, paste the failing lint output into your handoff, then delete the probe file.
4. `curl localhost:3000/api/health` returns 200 with the documented shape.

## Tests required

- One trivial Vitest test proving the runner is wired.
- One test asserting the ESLint boundary rule rejects `import ... from '@/polymarket'` inside
  `src/domain`. If that cannot be automated cleanly, document the manual proof from criterion 3
  in your handoff instead — do not fake it.
