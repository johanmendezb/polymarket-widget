Already on your branch and not to be redone: T5.1 (prompt assembly, structural blindness) and
T5.2 (Anthropic client, k-sampling, median-of-log-odds, IQR dispersion, the anchored diagnostic).
`evaluateGate` is on `main` from E2, and the four read routes are there too.

Do **not** build the AI panel UI. That is T5.4 and it needs T4.4.

Read `docs/05-ai/AI_SYSTEM.md` and `docs/04-architecture/API_CONTRACTS.md` for
`POST /api/ai/forecast`.

## The blend

Blend the model's estimate with the market price at the **pre-registered weight** in
`AI_SYSTEM.md`. Two things about it are non-negotiable:

- **Blend in log-odds space**, not probability space, consistent with the aggregation.
- **The weight is pre-registered.** It is not tuned, not fitted, and not adjusted to make a demo
  look better. If you think it is wrong, say so in the handoff and leave it alone.

The market price is available here and that is correct — blindness is a property of the
*elicitation*, not of the pipeline. The blind prompt never sees a price; the blend deliberately
does. Keep that boundary obvious in the code so a later reader does not "helpfully" pass the
price upstream into the prompt input.

## Wiring the gate

`evaluateGate` is already written and tested. Wire it; do not reimplement it or add rules.

The gate must **name its reason codes** in the response. A recommendation the user cannot
interrogate is worse than no recommendation. Abstention is a first-class outcome, not an error
path — `insufficient_evidence` and a fired gate both produce a valid `Recommendation`.

## Route requirements

- `POST /api/ai/forecast`, body `{ marketId, tokenId, samples? }`.
- **Hard 45s server timeout.** Returns `AI_TIMEOUT` rather than hanging.
- **`AI_NO_EVIDENCE` returns HTTP 200**, not an error status, with an explicit empty-forecast
  shape. "I could not find sources I trust" is a correct answer and the product renders it as one.
- A schema violation retries once, then `AI_INVALID_OUTPUT`. Never partially render.
- **Every error here must be non-fatal to the rest of the widget.** Killing this route leaves
  search, market detail and the cost preview fully working — E6 asserts that with an E2E test, so
  do not create a coupling that would break it.
- The response carries full provenance: timestamp, model id, prompt version, sample count `k`,
  dispersion, and the blend weight. A displayed forecast without its provenance is a claim.

## Secrets and logging

`ANTHROPIC_API_KEY` is server-side only and **is not set in this environment** — do not look for
it, do not ask for it, and write no test that needs it. The transport is injectable; test against
a mock. Never log a full prompt or a full model response, and never a key, prefix, length or hash.

## Acceptance criteria

1. The route returns a valid `Recommendation` for a fixture market, with the gate's reason codes
   named when it fires.
2. `AI_NO_EVIDENCE` returns HTTP 200 with an explicit empty-forecast shape.
3. A timeout returns `AI_TIMEOUT`; a persistent schema violation returns `AI_INVALID_OUTPUT`
   after exactly one retry.
4. The blend is computed in log-odds at the pre-registered weight, matching a hand-computed value
   in a test.
5. Every response carries timestamp, model id, prompt version, k, dispersion and blend weight.
6. All tests pass with no network and no API key present.
